# VELA user guide

## Workspace

Scenes can be renamed, duplicated and reordered. Sources can be grouped, moved, renamed, reordered, hidden or locked; a locked source or parent group prevents edits. Properties opens source-specific settings and transforms; Filters edits supported microphone or video filters. Source visibility and locks are stored with the engine configuration.

The Audio Mixer displays measured source peaks, gain, mute, monitoring and scene/global scope. Hide removes a strip from the mixer without muting it; Show hidden sources restores strips. Global audio is supported for audio-only sources and display companions. Use Application Audio for global game or window audio. Duplicating a scene leaves existing global audio owned by the original scene.

Studio Mode separates preview and program. Select a scene to preview it, then use Take or Cut in Scene Transitions. The selected transition and duration determine Take. Disabling preview drawing does not stop output; Enable Preview restores it. Existing saved layouts are retained; View → Reset Workspace Layout restores all default docks, including the four Twitch docks. The application retains a single profile and scene collection.

Grouped transform coordinates are parent-local. OBS may rebase a group origin while retaining the same world placement after a resize; unchanged Apply operations retain placement. Capture-audio topology is chosen when creating the source.

Twitch activity and statistics require optional account permissions; use Reauthorize activity permissions when needed. Dismiss and Clear affect the local feed only and do not skip external alert playback. Lifetime channel views are unavailable. Real-account activity, actual capture and physical monitoring still require manual verification.


VELA opens a safe color scene on a fresh profile. Add scenes and sources with the + buttons. Display, window, game and audio devices activate only when explicitly added. Open **Advanced Audio Properties** from Sources or the View menu to adjust source audio. The Audio meters dock displays actual libobs peak readings in dBFS, with silence or an expired reading shown as -100 dBFS. The automation audio condition uses the loudest current source peak.

The top menu provides File, Edit, View, Docks, Profile, Scene Collection, Tools and Help. Use Docks to show or hide workspace and Twitch docks, File for Settings and folders, and Tools for global hotkeys and remuxing. Profile and Scene Collection indicate the current single configuration; switching between multiple profiles or collections is not supported.

Configure the base streaming endpoint and stream key in Settings. The key is protected separately with Windows DPAPI. Choose an absolute output folder. Start streaming, recording and replay independently. Save replay works while the buffer is active. Streaming status distinguishes connection from starting or reconnecting. Replay settings include 15, 30, 60, 120 and 300 second presets and a memory cap.

Open **Docks → Twitch channel** and **Docks → Twitch chat** to connect your account, edit channel information, and use chat. Follow the [Twitch setup guide](TWITCH.md) to register a public application and authorize it from VELA.

In **Add source**, choose Window or Game capture, select the target and enable **Capture audio from this application only**. For Display capture, also select an **Audio application**: a monitor has no single application audio stream. **Application audio** adds an audio-only source. Application capture includes the selected app's audio, potentially including multiple windows/tabs; it does not mute other configured sources. Disable or mute Desktop audio if it would capture the same sound twice. Audio availability depends on the Windows/OBS runtime and whether the application supports capture.

**Also save a separate recording track** initially sends that source to track 1 and a free recording track. Display capture's selected application shares the display source's controls and meter.

Select a **Microphone** in Sources and click **Filters...**, or right-click that microphone and choose **Filters...**. No filters are added automatically. Use **+** to add Compressor, Noise Gate or Noise Suppression, **−** to remove the selected filter, and the arrows to change processing order. Audio passes through the list from top to bottom. Uncheck a filter to bypass it without losing its settings. Changes apply immediately; **Defaults** restores only the selected filter's settings, and **Close** keeps your changes. Filter edits are saved when the dialog closes.

**Compressor** controls ratio, threshold, attack, release and output gain. **Noise Gate** controls open/close thresholds, attack, hold and release; the close threshold must be at or below the open threshold. **Noise Suppression** starts with Speex at −30 dB when available, with a slider and numeric level control. RNNoise appears when supported by the installed OBS runtime and has no suppression-level control. These filters affect the microphone before monitoring and output track mixing.

If an optional filter module or saved suppression method is unavailable, its row is marked **unavailable** and bypassed. The saved order, enabled preference and settings are retained, so installing a compatible runtime restores them. You can remove or bypass dormant rows, or choose a supported suppression method. These audio filters are available only for microphones; video sources have a separate supported three-filter catalog. Real microphone listening tests and perceptual tuning remain user-specific; the automated fixture uses synthetic samples and never opens a real microphone device.

In **Advanced Audio Properties**, clear **Active Sources Only** to include audio sources in other scenes. The status follows scene activation and source audio activity. Set volume in dB or select **Volume in %**. Unity gain is 0 dB or 100%. Use **Mute** to silence the source, **Mono** to downmix it, and **Balance** to adjust left/right level. **Sync Offset** accepts −950 to 20000 ms. Positive values delay the source audio.

**Audio Monitoring** uses the default Windows playback device. **Monitor Off** sends audio to the checked tracks. **Monitor Only (mute output)** sends it only to the monitor. **Monitor and Output** sends it to both. Monitor Only preserves the checkboxes so changing the mode restores the selected routing.

Check any combination of **Tracks 1–6**. Streaming and replay use track 1, so clear it for a recording-only source. Multiple sources on the same track are mixed together. Clear all six to exclude the source from every output track. Recording preserves track numbering through the highest assigned track, including silent gaps. Stop recording to edit assignments or add/remove sources on tracks 2–6. Volume, mute, mono, balance, sync offset and monitoring remain adjustable while recording. Most players play one track at a time. Select a track in your player or import all tracks into your editor.

Apply delay in the Stream delay dock. Increasing delay holds output and may disconnect the ingest server; decreasing delay cuts content. Effective delay is approximate, and dropped packets include intentional cuts.

The Automation dock contains a visual rule editor. Add or edit a rule, choose a unique ID, enabled state and priority, then add OR condition groups. Conditions within a group are ANDed; an empty group matches everything. Rules with no groups never match. Higher priority wins, with lexical ID breaking ties. The editor exposes process, foreground process, window title, output state, audio peak, elapsed time and hotkey conditions. Process names include the .exe suffix and use lowercase. External flags require an integration to supply them; the current native adapter supplies none.

Actions execute in their listed order. Select a row and use Move action up to reorder it. Actions include scene selection, streaming/recording/replay start and stop, replay saving, delay, plugin action and log. Debounce requires a continuous match before triggering. Cooldown limits repeat frequency; persistent winners trigger once unless Repeat while winning is enabled. Rule testing checks the current snapshot without executing actions. A fallback scene is selected when no rule matches. Manual scene selection or Pause automation gives a 30 second manual override. The controller evaluates every 500 ms and keeps at most 100 log entries.

The VALORANT (100), CS2 (90), Discord (40) and Desktop (0) examples are disabled. Create/select their intended scenes and edit their targets before enabling them. Import/export uses versioned FeatherCast automation JSON. Invalid imports preserve existing rules; exports contain no stream settings or keys. URL arguments are rejected. Importing a document with automation enabled activates its rules, so review trusted documents before import.

Global hotkeys are configured through Tools > Global hotkeys or Settings > Hotkeys. Supported single chords combine Ctrl, Alt, Shift or Win with letters, digits, Space or F1–F24. Conflicts and unsupported chords are reported. IDs include toggle_stream, toggle_record, toggle_replay, save_replay, delay_0, delay_30, delay_90 and manual_scene. These IDs are also available to automation hotkey conditions for a two second pulse; use a debounce below two seconds. A hotkey's direct action also executes. Registrations are released on close. A manual_scene hotkey opens the scene selector and pauses automation for 30 seconds.

Remux MKV to MP4 converts a completed recording without re-encoding. Choose a new MP4 filename; existing files are preserved. The helper writes a temporary file in the destination folder and renames it only after finalizing the MP4. The original MKV remains intact. Cancel remux or closing FeatherCast stops the helper and removes its temporary output. Remuxing requires recording to be stopped and accepts compatible audio/video streams in Matroska files.

General settings gate replay and plugin actions/loading, choose dark/light theme, and disable preview drawing. View also toggles preview immediately while outputs run. Automation has its own enable switch. Settings that reset encoders require all outputs stopped. Disabling plugins gates their actions and future loading; already loaded DLLs remain in memory until exit. Plugins are trusted in-process code and must be selected explicitly.

Configuration, source audio/visibility, theme and dock layout persist. Engine/layout settings save every 30 seconds and on exit; automation edits save immediately. Closing stops active outputs through backend shutdown. CPU utilization is measured and cached for at least 500 ms; GPU utilization remains unavailable. A QWidget screenshot does not include the native preview HWND and cannot establish preview visibility.

For isolated testing, use an absolute --config-directory; this also selects a separate DPAPI credential namespace. --screenshot <absolute.png> saves the real main widget. --ui-self-test <absolute.json> checks serialization, invalid-import preservation, controller actions/override, native hotkey registration/conflicts/event dispatch, actual audio peaks and engine scene preservation, and saves macro-editor.png in that test configuration directory. Combine with --quit-after 10. It creates a temporary explicit 440 Hz test source and removes it before exit. Native hotkey event testing posts WM_HOTKEY to this application's event loop; it does not inject physical keyboard input or establish delivery from another foreground application.
